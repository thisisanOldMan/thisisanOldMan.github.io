02.1

代表案例

2025–2026｜企業合作

大型語言模型客戶輪廓分析系統

LLM SOLUTION

將分散於長篇客服與銷售對話中的需求、偏好及互動訊號，轉為具明確資料契約與持續更新機制的客戶輪廓。

FLOW　對話資料 → Schema 設計 → LLM 結構化擷取 → 驗證修復 → 增量更新與批次輸出

我的責任

負責 Persona 資料模型與後端資料流設計，建立結構化擷取、輸出驗證、異常修復、增量合併及批次輸出流程。

關鍵決策

以統一資料契約與 Provider Adapter 隔離模型供應商差異，使擷取、驗證與更新邏輯不依賴單一模型端點。

技術

Python、Prompt Engineering、JSON Schema、Provider Adapter、pandas。

工程驗證

完成單筆約 2 萬中文字的結構化擷取與輸出驗證，涵蓋解析、修復、增量合併及 JSON／Excel 交付流程。

2025｜研究型系統

會議諸葛｜Realtime Agent 與任務事件流程

AGENT WORKFLOW

建構即時會議 Agent 的語音脈絡、工具呼叫與任務狀態流程，使模型判斷能進一步驅動可保存、可追蹤的系統事件。

FLOW　語音脈絡 → Realtime Agent → Function Calling → Webhook／任務事件

我的責任

負責 Realtime Agent 與工具契約整合，串接 WebRTC、Function Calling、Webhook、會議資料及任務狀態。

關鍵決策

以結構化事件作為模型與應用系統的整合邊界，使即時互動、工具執行與會後任務共用一致狀態。

技術

TypeScript、React、Realtime／WebRTC、Function Calling、Webhook。

系統成果

整合即時逐字稿、工具呼叫、待辦、提醒與任務狀態，使會中事件能延續為會後可追蹤的工作項目。

2025–2026｜開源專案客製

LightRAG 可追溯知識問答服務

RAG / KNOWLEDGE GRAPH

基於 HKUDS／LightRAG 客製知識問答流程，整合多路檢索、知識圖譜與來源追溯，使回答能回傳實體、關係及原文片段。

FLOW　文件處理與索引 → 檢索（向量／圖譜／Hybrid） → 回答生成與來源追溯 → Graph Search

我的責任

負責查詢 API、來源追溯、Graph Search、檢索設定、繁中 WebUI 與本機服務環境的客製及整合。

關鍵決策

保留 upstream RAG 核心與 bindings，將客製範圍集中於來源追溯、檢索設定、查詢 API 與使用介面，保留後續升級路徑。

技術

Python、LightRAG、NetworkX、RESTful API、React、知識圖譜、檢索（向量／圖譜／Hybrid）。

實機驗證

完成本機 Server／WebUI 啟動、知識圖譜載入、節點關係呈現與查詢流程檢查；公開畫面使用 16 節點、18 關係的合成資料。

02.2

延伸案例

GENAI AUTOMATION

好奇兄弟雲端｜AI 行銷影片流程自動化平台

專案目的：讓商家直接在 LINE 提交商品素材，將文案、旁白、字幕與影片生成整合為可預覽、修正及重新生成的單一流程。

核心做法：以 n8n 編排 LINE Webhook 觸發的生成工作流，串接 LLM、TTS 與影片生成服務；透過非同步任務、狀態追蹤及人工確認管理生成與交付。

n8n · LINE Messaging API · LLM · TTS · 影片生成 API · Supabase · 非同步任務編排 · Human-in-the-loop

應用價值：將素材提交、內容生成、修改與交付收斂於 LINE，降低跨工具操作與人工交接成本。

負責範圍：主導需求拆解、工作流與狀態模型設計，整合生成服務、異常處理、人工確認及使用者／任務資料隔離。

RESEARCH PROTOTYPE

COMPASS｜多回合對話策略決策框架

研究目的：評估候選對話策略對後續狀態與終局結果的影響，避免只依單輪回應選擇下一步策略。

核心做法：將策略選擇建模為有限視界決策問題，結合狀態轉移預測與成功／失敗路徑成本，比較候選策略的多步對話路徑。

有限視界決策 · 狀態轉移預測 · 路徑成本分析 · LLM 對話模擬

研究結果：在 CraigslistBargain 與 GPT‑3.5 的固定模擬設定下，成功率為 74.86%，成功對話平均 4.858 輪。

負責範圍：提出決策方法，完成演算法實作、基準方案、實驗設計與結果分析。

AGENTIC RAG PROPOSAL

意圖驅動智慧旅遊｜Agentic RAG 架構提案

專案目的：將地點、時間、偏好與限制等自然語言需求，轉換為可補問、可查證且能持續調整的個人化行程。

核心做法：以意圖辨識、Slot Filling 與檢索路由建立 Agentic RAG 決策迴圈，依查詢需求與證據充分度決定回答、補問、切換檢索來源或重新檢索。

Agentic RAG · 意圖辨識 · Slot Filling · 檢索（BM25／向量／Hybrid）· 知識圖譜 · 檢索路由

應用價值：將條件補齊、跨來源檢索與行程調整整合於同一段對話，降低反覆查找及手動整理負擔。

負責範圍：規劃意圖驅動的檢索流程、檢索路由、多來源資料融合、回應生成與評估流程。

MODEL EVALUATION

仁愛醫院合作｜肝癌存活風險建模與比較

研究目的：建立可重複的肝癌存活分析流程，以一致的資料切分與評估標準比較統計、集成與深度學習模型。

核心做法：比較五種存活模型；以 C-index 評估風險排序能力，搭配 Kaplan–Meier、個案存活曲線與 SHAP 分析群體趨勢、個別風險及特徵貢獻。

Survival Analysis · CoxPH · Random Survival Forest · Gradient Boosted Cox · DeepSurv · LogisticHazard · C-index · Kaplan–Meier · SHAP

研究價值：讓五種模型共用一致的資料處理、切分與評估介面，提升跨模型比較的一致性。

負責範圍：負責資料前處理、五種模型建置、驗證、結果比較及模型解釋分析。

SPECIFICATION

台鐵／世曦工程｜鐵道 AI 招標規格協作

專案目的：將語音辨識、鐵道術語校正與技術文件問答需求，轉化為可供招標、方案比較及驗收的 AI 系統規格。

核心做法：將方案拆為語音辨識與領域術語校正、技術文件檢索問答兩條能力鏈，並定義資料範圍、系統邊界及驗收方式。

ASR · 領域術語校正 · RAG · 檢索（關鍵字／向量）· 知識圖譜

交付價值：形成涵蓋功能需求、技術方案、資料條件與判定基準的招標及評選規格。

負責範圍：負責場域需求轉譯、檢索方案設計、功能規格與驗收條件整理。
